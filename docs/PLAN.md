# 视觉机械臂仿真项目：框架与 MVP 实施方案

- 项目名称：Vision Arm Lab（目录名为暂定工程名称）
- 方案日期：2026-09-27
- 状态：核心 MVP（M0–M5）已完成，专家和视觉均通过固定 50 种子验收，详见 [M5.md](M5.md)。
- 决策依据：用户已确认的技术路线、MVP 范围及记录策略。
- 开发规范：遵循根目录 [AGENTS.md](../AGENTS.md)，包括 Git 分支与提交规范、模糊需求先询问及最小实现原则。

## 1. 目标与原则

构建用于视觉机械臂仿真、算法开发与验证的轻量项目，支持从传统视觉与控制算法逐步扩展到模仿学习、强化学习和 VLA。

首版跑通“视觉观测 → 策略 → 机械臂执行 → 评测”的闭环，数据记录按需开启。通过传统视觉策略与真值专家策略验证接口和执行流程。

设计原则：

1. Python 模块化单体，默认同进程调用；只实现一个仿真后端。
2. 稳定观测、动作、任务和评测契约，核心契约不依赖 robosuite 类型。
3. 复用现有机械臂资产和控制器，不从零实现物理、IK 或底层控制。
4. 场景参数配置化，扩展以实际需求驱动，不预建通用平台。
5. 先完成专家闭环，再引入视觉误差，最后完成批量验收。
6. 日常运行默认不落盘；所有高容量记录均显式开启。
7. 架构支持环境变化，但不承诺首版颜色分割算法具备广泛泛化能力。

## 2. 已确认的 MVP 范围

| 项目 | 已确认范围 |
| --- | --- |
| 用途 | 暂时只做仿真研究 |
| 操作系统 | Ubuntu 22.04 或更高版本；开发前确定具体版本 |
| GPU | 用户提供为 NVIDIA RTX 4060、16GB 显存；环境检查时核实型号和显存 |
| 仿真 | MuJoCo + robosuite，首版单环境运行 |
| 机器人 | Franka Panda 七自由度机械臂与平行夹爪 |
| 场景 | 桌面、单个方块、一个无实体障碍的目标标记区域 |
| 任务 | 抓取方块并放入目标区域 |
| 相机 | 一台固定 RGB-D 相机；已知相机标定与桌面高度 |
| 抓取 | 固定俯视抓取姿态；限制方块尺寸和朝向范围使其适用 |
| 随机化 | 方块平面位置与绕竖直轴的朝向 |
| 传统策略 | 颜色分割、深度反投影、坐标变换、抓取状态机 |
| 专家策略 | 使用仿真真值定位方块，复用同一抓取状态机与执行模块 |
| 使用方式 | 命令行启动、仿真窗口观察、离屏批量评测 |
| 附加操作 | 控制接口简单时加入键盘 XYZ 移动、夹爪开合和重置 |
| 数据保存 | 配置、指标、动作、观测和视频均按记录模式或独立选项保存 |

首版允许使用的先验包括相机内外参、桌面高度、目标颜色范围和配置给定的目标区域。视觉策略不得读取方块真实位姿、真实分割标签或其他未声明的仿真特权信息。

## 3. 首版不包含的内容

- 真机、ROS 2、MoveIt 2 或 ros2_control 集成。
- 第二仿真后端、分布式服务、动态插件系统和通用消息总线。
- IL/RL 训练、VLA 模型下载、微调与推理服务。
- Web 界面、多机械臂、多环境 GPU 并行训练。
- 多物体目标识别、任意六自由度抓取、复杂障碍避让。
- 自动标定、逼真深度传感器误差建模、完整域随机化系统。

这些内容可作为后续迭代，不作为 MVP 验收前置条件。

## 4. 技术栈与模块职责

首版使用 Python、NumPy、MuJoCo、robosuite、OpenCV，以及 YAML 配置、dataclass 数据结构和必要的 pytest 检查。点云处理、PyTorch、LeRobot 等在实际功能需要时加入，避免预装重型依赖。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| contracts | 观测、动作、动作规格、策略生命周期的数据契约 | 不引用仿真器内部对象 |
| backends | 加载仿真、读取传感器和机器人状态、推进与重置 | 首版仅实现 robosuite |
| tasks | 场景配置、初始化、随机化、目标和终止判定 | 评测真值不混入视觉策略观测 |
| perception | 颜色分割、深度处理、目标位置估计 | 明确依赖的标定和先验 |
| policies | 真值专家与视觉策略，维护抓取状态机 | 可替换定位组件或整个策略 |
| control | 动作转换、约束检查、控制器调用和夹爪控制 | 复用框架已有控制器 |
| runner | 运行与重置、时序、批量实验和评测汇总 | 不实现感知或控制算法 |
| data | 可选记录、容量管理、视频与命令回放 | 关闭时不创建实验结果文件 |

### 4.1 核心契约

- **Observation**：具名相机集合、可选深度、标定、机器人状态、时间戳，以及可选语言指令。缺失传感器必须明确表示。
- **ActionSpec**：控制模式、坐标系、单位、关节顺序、绝对/增量语义、夹爪含义与时间间隔。
- **ActionChunk**：允许包含 H 个动作，单步策略使用 H=1；不要求首版实现异步推理或复杂队列。
- **Policy**：初始化/重置策略状态、接收观测、返回动作，声明所需输入与动作规格。
- **Backend**：声明能力、获取观测、接受控制命令；仿真额外提供推进和重置。
- **Task/Evaluator**：初始化分布、成功/失败/超时判断、指标统计；特权状态通过独立通道读取。

首版只支持验证过的一种末端控制模式和夹爪语义，不因接口可扩展而实现所有动作类型。不支持的模式明确报错。物理步进、控制、相机采样的频率分别配置；各数值在控制器验证后锁定。

### 4.2 算法流程

视觉策略：RGB-D → 颜色掩膜 → 深度有效性检查 → 反投影和坐标转换 → 方块位置估计 → 抓取状态机 → 执行。

专家策略：仿真方块位姿 → 同一抓取状态机 → 同一执行模块。

抓取状态机包含接近、下降、夹取、抬升、移动、释放及等待判定。各阶段设超时；首版不加入无限重试或复杂恢复规划。定位失败、抓取失败、掉落、未到达区域和超时尽量使用可区分的结果标签。

## 5. 多元环境与泛化评测扩展

| 维度 | 首版落实 | 后续扩展 |
| --- | --- | --- |
| 物体 | 通过物体列表描述单方块 | 多形状、尺寸、材质、干扰物 |
| 相机 | 具名相机集合，实际只启用一台 | 腕部相机、多视角、位姿变化 |
| 任务 | 独立描述目标对象与放置区域 | 多目标、目标选择、其他操作任务 |
| 随机化 | 明确参数范围与随机种子 | 外观、光照、物理参数和传感器噪声 |
| 策略先验 | 在配置和策略能力声明中显式列出 | 逐项减少先验或替换感知算法 |
| 评测 | 场景分布与策略配置分开 | 使用相同评测协议比较不同算法 |

评测分为开发场景、同分布测试场景、分布变化测试场景。首版实现前两类，预留第三类的配置组织方式；不提前实现所有随机化维度。

开发与测试使用独立种子集合。固定 50 个测试种子后，不根据结果删换困难种子。仅更换种子不视为充分的泛化验证。后续应先分别改变单个因素，再增加组合变化，并按条件分别报告表现。

## 6. 可选记录与存储控制

### 6.1 记录模式

| 模式 | 行为 | 用途 |
| --- | --- | --- |
| off（默认） | 仅终端输出结果，不保存实验文件 | 日常开发和调试 |
| summary | 保存汇总、逐回合结果、有效配置、种子和版本等轻量信息 | 批量评测和正式验收 |
| debug | 在 summary 基础上，按独立选项保存附加记录 | 问题定位 |

动作、原始观测、视频分别开关，默认全部关闭。选择 debug 本身不自动打开所有高容量数据。配置和指标文件也只有显式启用相应记录模式才保存。

### 6.2 容量约束

- 视频支持全部回合、仅失败回合、指定回合；提供数量、分辨率、帧率上限。
- 原始 RGB/深度不随视频自动保存；启用时限制采样频率或回合数量。
- 设置单次运行记录预算，临时视频文件也计入预算；为轻量结果预留空间。
- 达到预算后停止附加记录并提示，评测继续；标注哪些记录不完整。
- 写入失败或磁盘不足不应使控制与评测循环崩溃；终端报告无法保存的内容。
- 仅失败视频使用流式编码的有界临时缓存，成功后丢弃，失败后保留；不在内存无限积累原始帧。
- 记录器只清理自己创建的临时数据；不自动删除历史实验结果。
- 正常退出清理临时数据；异常中断的遗留文件提供显式识别和清理方法。
- 数量、预算、帧率等默认数值在开发时用实际文件大小验证后确定。

首版不同时维护多种完整数据集格式。先实现轻量元数据和可选时序记录，保留后续 LeRobot 导出的字段与转换边界；完整导出器后移。

回放定义为视频查看及在相同环境配置下重新执行记录的控制命令。命令回放仅适用于开启动作记录且记录完整的回合，不承诺跨软件版本逐帧一致。

## 7. MVP 验收标准

| 类别 | 标准 |
| --- | --- |
| 环境 | 可加载 Panda、桌面、方块和目标区域；支持窗口与离屏运行 |
| 任务成功 | 方块释放后完整落入目标区域，稳定保持 1 秒 |
| 稳定判定 | 位置/速度等判定阈值显式配置；验收前锁定 |
| 专家策略 | 固定 50 个测试种子，成功至少 48 次（满足 ≥95%） |
| 视觉策略 | 同一批 50 个种子，成功至少 45 次（满足 ≥90%） |
| 信息隔离 | 视觉策略不读取物体真实位姿或隐藏特权状态 |
| 可选记录 | off 无实验文件；summary 可复查；动作、观测和视频开关有效 |
| 容量控制 | 小预算条件下停止附加记录，评测仍能完成 |
| 回放 | 对一个完整记录的短回合验证命令读取和重放 |
| 结果呈现 | 汇总成功率、完成时间和失败原因；明确策略观测来源 |

正式成功率验收使用 summary 模式，不强制保存动作、原始观测或视频。所有尝试都计入结果；环境或软件错误单独报告，不能静默跳过并补抽种子。

若没有达到成功率目标，应报告实际表现并定位原因，不通过放宽成功条件或缩小已锁定测试范围宣称通过。50 回合结果仅用于当前配置下的 MVP 验收，不等同于广泛泛化或可靠性保证。

## 8. 分阶段任务与时间控制

以下是单人有效开发时间的规划估算，不是交付承诺。1 人日按约 6 小时有效工作估算，不含环境下载等待和用户讨论等待。核心 MVP 约 6–9 人日，键盘操作另计最多 0.5 人日。每个任务尽量在半天左右产生可检查结果。

执行顺序：M0 → M1 → M2 → M3 → M4 → M5。记录方案在 M0 确定，完整实现放在闭环跑通后，避免先建设复杂数据系统。

| 阶段 | 子任务 | 估算 | 完成门槛 |
| --- | --- | --- | --- |
| M0 环境与契约 | T01 核实系统/GPU并选定兼容版本；T02 最小渲染与 Panda 控制冒烟检查；T03 锁定动作、观测及配置契约 | 0.5–1 人日 | 窗口/离屏均可运行，控制模式明确，依赖可复现 |
| M1 基础框架 | T04 项目结构与配置入口；T05 后端和观测适配；T06 单方块任务、种子与成功判定 | 1–1.5 人日 | 可重置、观测、执行和终止，允许手动检查成功判定 |
| M2 专家闭环 | T07 真值专家和抓取状态机；T08 执行约束与阶段超时；T09 少量开发种子验证 | 1–1.5 人日 | 固定场景抓放成功，随机开发场景可诊断，失败不会无限等待 |
| M3 视觉闭环 | T10 RGB-D 定位与坐标转换；T11 替换专家定位输入；T12 无效深度/检测失败处理与信息隔离检查 | 1–1.5 人日 | 视觉策略完成抓放，可比较估计误差和专家表现 |
| M4 评测与记录 | T13 批量评测与 off/summary；T14 可选动作/观测记录及命令回放；T15 流式视频、筛选和容量预算 | 1.5–2 人日 | 默认零结果文件；开启记录可复查；低预算验证通过 |
| M5 验收与交接 | T16 锁定测试配置并运行两策略各 50 回合；T17 修复验收阻塞问题；T18 使用说明与限制记录 | 1–1.5 人日 | 逐项报告验收结果、实际成功率及已知限制 |
| M6 可选键盘操作 | T19 XYZ 移动、夹爪开合、重置及唯一控制权切换 | 最多 0.5 人日 | 手动与策略控制不同时下发；接入复杂时延期 |

### 8.1 防止开发周期膨胀

1. 每个阶段交付可运行结果和简短检查记录，不等所有模块完成才整体验证。
2. 首先复用现有任务/资产；只修改实现单方块放置所必需的部分。
3. 一次只支持一个机器人、一个控制模式、一台相机和一种传统定位方法。
4. 每阶段达到门槛即进入下一阶段；非阻塞优化写入后续清单。
5. 子任务超过估算上界时，先报告阻塞原因与最小解决方案；涉及已确认目标变化时再讨论。
6. 不自建 IK、运动规划器、训练框架或视频编码器，使用已有能力和库。
7. 键盘操作不阻塞 MVP；复杂重试策略、自动历史清理、数据集格式转换均后移。
8. 将坐标转换、成功判定、记录关闭及容量上限作为重点检查，避免为简单封装铺设大量重复测试。
9. 冒烟与开发阶段使用少量回合、低分辨率和 off 模式；完整验收仅在策略与评测条件稳定后运行。
10. 完整验收后，仅在代码变更影响结果或仍有未解决问题时重复相关测试。

## 9. 风险与处理路径

| 风险 | 对策 |
| --- | --- |
| 系统、驱动、依赖或离屏渲染兼容性 | M0 优先验证并锁定版本，不在此之前扩展工程 |
| 深度定义、图像方向或坐标变换错误 | 使用已知几何点检查，专家与视觉对照诊断；真值仅用于诊断 |
| 接触和夹爪参数使抓取不稳定 | 先验证专家策略，再引入视觉；限定尺寸和可达工作空间 |
| 固定姿态抓取的适用范围有限 | 在配置和文档明确假设，后续用姿态估计/抓取算法替换 |
| 验收条件过易或开发调参污染测试 | 开发/测试分离，验收前锁定范围、种子和终止规则 |
| 视频和观测占用存储或拖慢执行 | 默认关闭、流式编码、采样和预算；记录仿真时间与墙钟时间 |
| 泛化需求导致过度抽象 | 保留数据与配置边界，每增加一个实际变化因素再补对应实现 |

## 10. 开发前与开发中待确定事项

以下参数尚待确定。开发时先通过文档与实测收集依据；对于仍不确定的实现选择，集中提出建议并与用户确认，不自行猜测。已确认的参数不重复询问：

- 最终 Ubuntu、Python、MuJoCo、robosuite 及渲染依赖版本。
- 方块尺寸、质量、摩擦，桌面与目标区域尺寸。
- 可达采样范围、朝向范围、物体和目标区域的最小初始间距。
- 相机位置、分辨率、深度有效范围和颜色阈值。
- 控制频率、动作步长、夹爪阈值、阶段与整回合超时。
- 稳定判定阈值、记录预算、视频数量及帧率默认值。

上述参数在正式验收前固定。若实现需要改变任务、算法范围、验收目标或引入明显的新依赖体系，应先与用户讨论。

## 11. 后续迭代候选

按需求选择，不默认全部实施：

1. 新增干扰物与外观变化，建立首组分布变化评测。
2. 腕部相机、多视角和更一般的目标位姿估计。
3. LeRobot 数据导出及 ACT/其他模仿学习基线。
4. 一个 VLA 适配器，验证预处理、动作归一化、动作分块与推理延迟。
5. 大规模并行需求出现后评估 ManiSkill 或 Isaac 生态。
6. 真机需求明确后再接入 ROS 2、厂商驱动及相应控制适配。
