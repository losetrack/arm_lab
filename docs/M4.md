# M4 记录、容量和回放

状态：记录与回放检查已通过，默认 `off`。实现为 `data.py`、`replay.py` 和 `maintenance.py`。

## 模式与格式

- `off`：仅终端结果；不创建运行目录，也不采集版本快照。
- `summary`：记录有效场景、动作规格、策略/视觉参数、种子列表、Python 与依赖版本、源码 SHA-256、可用的 Git 提交号，以及逐回合结果和汇总。
- `debug`：同 summary；动作、原始观测、视频各自显式开启，不随 debug 自动开启。

动作按控制步写 JSONL，包含物理单位的位姿增量、夹爪、步号和仿真时间。原始观测按采样频率写独立 NPZ，包含 RGB、米制深度、标定、时间与机器人状态。视频为 FFmpeg 编码的 fragmented MP4，帧从有界管道流式输出；没有完整回合原始帧列表。

元数据带有源码和依赖快照。当前仓库尚无 Git 提交时，`git_head` 明确为 null，不能伪造提交号；源码摘要仍能识别执行的代码。运行目录名称包含 UTC 时间与随机后缀，不覆盖既有记录。

## 默认上限与实测

| 项目 | 默认值 |
| --- | --- |
| 单次运行预算 | 128 MiB |
| 轻量结果预留 | min(256 KiB, 总预算的一半) |
| 原始观测 | 2 Hz、最多前 2 回合（只有显式启用才记录） |
| 视频 | 10 FPS、256×256、最多保留 3 个回合（默认关闭） |
| 视频筛选 | 全部、仅失败、指定零基回合序号 |

1 秒、20 个控制步的实际检查产生：动作约 2.7 KB、两帧观测各约 72 KB、视频约 9 KB。以此确认默认预算适合当前 256×256 场景；实际空间仍由统一预算限制，而不是根据估算无限写入。

预算覆盖元数据、动作、观测、正式视频和临时视频。写入前在同一锁下检查字节预算，视频编码输出同样经过该入口。到上限后停止附加记录并提示，保留轻量结果空间。被截断的视频不作为完整视频保留；完整性标志写入结果。预算耗尽不会停止仿真或改变任务判定。

仅失败视频逐回合编码至本运行的 `.tmp-video-*.mp4`；成功后删除，失败后保留为 `video.mp4`。数量限制控制保留的视频数。录制器只删除自己创建的临时文件，不删除历史运行结果。

## 验证

- off 不创建目录；debug 不带独立开关时只有轻量文件。
- 动作预算耗尽后，循环仍执行全部指定步数，结果标记动作不完整，summary 可保存。
- 随机图像的视频预算测试：编码输出达到预算后停止保存，评测步数不受影响，临时文件清理，磁盘占用未超过预算。
- 模拟磁盘写满：明确打印错误，不把写入错误抛入控制循环，仍返回评测结果。
- 全部、失败、指定回合视频筛选通过；保留的视频可由 OpenCV 解码。
- 实际小预算运行（20,971 字节）执行完 30 步：只保存前 10 条动作，观测和视频标为不完整，终端和 summary 均报告 `step_limit` 而非软件错误。
- 完整抓放低预算压力检查：20,971 字节预算下仍执行 663 步并成功放置，仅前 10 条动作保存完整，其他附加记录标为不完整；最终占用 8,390 字节，无残留临时视频。
- 实际完整短回合保存 20 条动作后，命令回放完成同样的 20 步、1 秒仿真。

## 回放与清理

回放只接受标记完整、步数及时间连续、源码和依赖版本匹配的动作记录。使用记录内的场景与种子，不重新执行策略，不承诺跨版本逐帧一致。视频可直接用支持 MP4 的播放器打开。

正常退出和 KeyboardInterrupt 会关闭编码器并清理未完成临时视频。强制终止进程或断电可能留下临时文件，可显式列出：

```bash
PYTHONPATH=src python -m vision_arm_lab.maintenance runs/<run-directory>
```

检查列表后，加 `--delete` 只删除该运行下符合命名规则的临时视频；需要运行元数据的格式标识匹配。不会扫描并删除其他历史运行。

磁盘完全不可写时，轻量结果也可能无法保存；错误会报告至终端。这是文件系统限制，不能宣称所有情况下 summary 必然可落盘。
